System Capabilities

What the system does

Everything described below is built, tested, and actively operational. Designed specifically to handle real-world organizational complexity across multiple companies and branches.

01 / ORGANISATION

Structure & Employment History

Supports six organizational levels—holdings, group, company, division, department, and branch. Several distinct companies live in one installation with strict mutual isolation.

  • Dated reporting lines preserve supervisory history
  • Custom rank ladder linked to role seniority
  • Bulk staff import with pre-commit dry-run preview
  • Separates historical corrections from date-effective events
02 / GOALS & KPIS

Target Setting & Weight Enforcement

Measures, baselines, goals, and weights for set periods. Enforces that each individual's target weights total exactly 100% before evaluation cycles can close.

  • Reusable organization-wide KPI library
  • Periodic check-ins with automatic achievement math
  • Two-stage approval: Supervisor and optional HR audit
  • Per-role task indicator scorecards
03 / EVALUATIONS

Appraisal Cycles & Calibrated Forms

Handles Annual, Probationary, Semi-Annual, Project, and KPI-based reviews as pure configuration rather than distinct custom code.

  • Form builder with sections, rating scales, and weights
  • Calibrated score calculated out of 100 points
  • Approval chain: Self, Supervisor, Dept Head, Moderation
  • Completion gate names the specific blocking reviewer
04 / PEER INPUT

360° Multi-Source & Peer Feedback

Panel rules configure who can evaluate whom by rank distance and organizational branch, eliminating rater bias and administrative chasing.

  • Automated sampling according to rank rules
  • Automatic substitute drawn when a reviewer declines
  • Eligibility filters exclude peers without working history
  • Distinct weighted instruments for peer assessments
05 / DEVELOPMENT

Competencies, IDP & PIPs

Version-controlled competency library mapped to job profiles. Identifies skills deficits and governs structured improvement plans.

  • Position benchmark requirements & automatic gap analysis
  • Career progression routes with typical dwell times
  • Formal Performance Improvement Plans (PIPs)
  • Strict milestone check-ins with immutable final outcomes
06 / ANALYTICS

Calibration, 9-Box & Scoped Views

One clear screen per role tier: Employee, Supervisor, Dept Head, and HR. Gives executives cross-divisional calibration visibility.

  • Nine-box talent grid (Performance vs. Potential)
  • Rater generosity vs. strictness comparison curves
  • Audit log of all moderation meeting rating revisions
  • Fast spreadsheet exports scoped to current user rights

Operational Lifecycle

How an evaluation cycle progresses

The software moves each appraisal through a deterministic state machine. Nothing skips gates, and ratings cannot be rewritten after final sign-off.

1
Target Agreement & 100% Weight Verification

Employee and supervisor agree on periodic targets from the KPI library. The period cannot open until weights total 100%.

Pre-Cycle Gate
2
Form Auto-Assignment & Self-Appraisal

Forms automatically match staff classification. Employee submits their self-review and achievement narratives.

Draft / Self
3
Concurrent Supervisor & Peer Input

Supervisor rates weighted line items. In parallel, sampled peer reviewers complete separate weighted peer forms without cross-visibility.

In Review
4
Department Head Review & Moderation (Calibration)

Department head can approve, revise, or return for corrections. Calibration meetings compare rating distributions across divisions.

Moderation
5
Formal Release, Employee Acknowledgement & Archive

Evaluation becomes visible to the subject only upon release. Employee sign-off is logged, and final scores are frozen forever.

Final / Frozen

Architecture & Data Protection

Why security sits in the database kernel

Almost every business application checks permissions at the application door. If code has an unexpected flaw, or someone queries the API directly, protection drops.

This system puts access rules on each record using PostgreSQL Row-Level Security (RLS). When the application issues a query, it connects as that specific user context. Records outside their authority are never returned.

Application bugs cannot leak records Because unauthorized rows never leave the database engine, they cannot be accidentally exposed by screens or exports.
Attempted unauthorized access returns "not found" Returning "forbidden" confirms that a record exists. For appraisal records, confirming existence is itself a privacy disclosure.
Zero stored passwords Delegates sign-in to your Active Directory / LDAP. Deactivating a departed employee in the company directory immediately terminates access here.

Scope Clarity

What the system deliberately does not do

These boundaries are explicit architectural choices rather than oversights. Keeping them separate protects personnel data privacy and avoids software bloat.

Excluded Function Design Rationale & How It Is Handled
Payroll Calculation Payroll carries different statutory tax calculations and reporting obligations. The system integrates via exports; it does not process payroll.
Daily Biometric Attendance Where attendance affects an evaluation score, it receives a summary count for the period rather than raw daily clock records.
Leave Management Leave approvals and balances stay in dedicated time-off software; period counts feed into reviews where required.
Salary & Compensation Figures There is no salary field in the database. Appraisals are reviewed by many supervisors; holding pay numbers would drastically widen exposure.
Government ID Numbers No SSS, TIN, PhilHealth, or Pag-IBIG numbers are stored. Their complete absence eliminates major statutory breach liabilities under data privacy laws.
Direct Document/File Hosting Portfolios and work evidence are referenced by URL link to your existing corporate document stores (Google Drive, SharePoint, or internal network shares).
